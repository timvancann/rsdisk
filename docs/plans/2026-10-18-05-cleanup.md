# Cleanup Implementation Plan

**Goal:** find what to delete (search), mark it, review it, and move it to the Trash; rescan
a folder or scan a cloud folder without restarting.
**Architecture:** Marks, search matching and tree grafting are plain logic with tests (marks
and search in the app crate, trashing bookkeeping and grafting in core). Trashing goes
through a `Trasher` trait whose real implementation calls Finder via the `trash` crate;
tests use a fake. Slow work (Finder, rescans) runs on background threads and the window
polls for the result, as the scan does.
**Tech Stack:** `trash` 5.x (`DeleteMethod::Finder`), rayon, gpui-kit 0.7.3.
**Spec:** `spec.md` §2.8, §2.11, §2.12, §3.5, §3.8 (marked-items pane), §3.9, §3.10, §3.11.

## Global Constraints

- Trash only, through Finder, so "Put Back" works (§2.11). Never delete permanently. The
  scan root is never markable or trashable.
- Selection and marks are by node, never row index.
- Tests never touch the real Trash, except one `#[ignore]`d test on a temp file.
- Tim's UI rules apply. The first real trash makes macOS ask to let the terminal control
  Finder; say so in the dialog the first time it fails with a permission error.
- Gate and screenshots as in plans 03 and 04 (`RSDISK_NO_FOCUS` ignores keys, so marks and
  dialogs need Tim to try them).

## Plan sequence (this is Plan 5 of 5)

Needs plans 03 and 04.

### Task 1: Marks

**Files:** create `crates/app/src/marks.rs`; modify `browser.rs` if the browser owns them.
**Interfaces:** `Marks` over a tree: `toggle(id)`, `clear()`, `is_marked(id)`,
`covered(id)` (it or an ancestor is marked), `ids()`, `total_size(tree)`,
`total_files(tree)`. Rules: the root can't be marked; marking a folder drops marks on its
descendants; toggling an item inside a marked folder does nothing; removed nodes drop out.
**Tests:** each rule above; totals never double-count.

### Task 2: Trashing in core

**Files:** create `crates/core/src/trash.rs`; add `trash` to core.
**Interfaces:** `trait Trasher { fn trash(&self, path: &Path) -> Result<(), String>; }`,
`FinderTrash` (the `trash` crate, `TrashContext` with `DeleteMethod::Finder`), and
`trash_all(tree, ids, &dyn Trasher) -> TrashOutcome { removed: Vec<NodeId>, failed:
Vec<(NodeId, String)> }`, which trashes each path, removes each success from the tree and
re-runs `Tree::summarize` once at the end.
**Tests (fake trasher):** successes leave the tree and their ancestors shrink; a failure stays
and is reported with its message; the root is refused; folder colours update after
removal. An `#[ignore]`d test trashes a real temp file through Finder.

### Task 3: Marked pane and confirm dialog

**Files:** create `crates/app/src/cleanup.rs`; modify `view.rs`, `list_view.rs`,
`visual.rs`, `keys.rs` if needed.
**Interfaces:** `space` toggles a mark on the selected row, `u` clears marks. Marked rows
show a "marked" tag and the accent colour; marked cells in the visual get an accent outline.
A pane along the bottom appears while anything is marked: "N items, X GB", "d to review, u
to clear". `d` opens a dialog listing the marked paths with sizes and the total; `enter` or
`y` confirms, `esc` cancels. Confirming runs `trash_all` on a background thread; the dialog
shows progress, then what moved to the Trash and what failed (with reasons). Afterwards the
list, the visual and the totals reflect the removals and the marks clear.
**Verify:** Tim trashes something harmless (a scratch folder made for it) and checks "Put
Back" in Finder.

### Task 4: Search

**Files:** create `crates/app/src/search.rs` (matching) and the search UI in `cleanup.rs`
or `view.rs`.
**Interfaces:** `search(tree, query, limit) -> Vec<NodeId>` per §3.10: case-insensitive
subsequence match on names in parallel; `/` in the query matches earlier parts against
ancestors in order; score favours matches at the start of words and contiguous runs; ties
by size. UI: `/` opens a query line at the top with up to 20 results (path relative to the
scan root, size), updated as you type; `ctrl-n`/`ctrl-p` or arrows move, `enter` jumps
(`Browser::jump_to`), `esc` cancels; `n`/`N` step through the last results afterwards.
**Tests:** subsequence matching; word-start and contiguous matches outrank scattered ones;
`lib/cach` finds `Library/Caches` but not `Caches` elsewhere; ties go to the larger node;
removed nodes never match; an empty query returns nothing.

### Task 5: Rescan and cloud folders

**Files:** modify `crates/core/src/tree.rs` (graft), `view.rs`.
**Interfaces:** `Tree::graft(id, subtree: Tree)` replaces `id`'s children with the
subtree's: appends the new nodes, points `id` at the new child block, marks the old
descendants removed, applies the size and file-count difference to every ancestor, clears
`NOT_SCANNED`/`UNREADABLE` on `id`, and re-runs `summarize`. `r` rescans the current folder
and `c` scans the selected not-scanned cloud folder (§3.5), each on a background thread
with a "scanning ..." note in the header; the result is grafted in when it arrives.
Hardlinks seen in the rest of the tree aren't deduplicated against the rescanned part
(known, minor).
**Tests:** after a graft, sizes and counts at every ancestor equal a fresh scan of the same
temp tree; old children are gone from `children()`; flags clear; a graft of a now-empty
folder leaves no children; grafting twice works.
**Verify:** create a large file in a scratch folder while rsdisk is open, `r` there, see the
size change; `c` on `Library/CloudStorage` (Tim's OK first: it may touch the network).

## Rulings during execution

- Task 2: trashing is split like the unreadable search: `targets` (main thread),
  `trash_paths` (background, the slow Finder part), `apply` (main thread); `trash_all`
  composes them for tests and any CLI use.
- Task 3: `space` marks and then moves down, as dua does. Marked rows show "marked" in the
  accent colour; marked cells in the visual get an accent outline. Rows inside a marked
  folder show as marked too.
- Task 4: scoring also rewards a name that starts with the query and penalises long names,
  and tries every place the first letter occurs (so `data` finds `DerivedData` by its word
  start). Without that, `lib/cach` ranked a `.pyc` file called `ChaCha20...` above
  `~/Library/Caches`. Timing on Tim's home folder: 10 to 20 ms for typical queries, about
  120 ms for a single letter.
- Task 5: a rescan also finds its unreadable folders before grafting, on the same
  background thread, and replaces the scan's errors under that path.
- Not verified by me (needs keys or the real Trash): marking, the dialog, trashing and Put
  Back, the search box, `r` and `c` live. Verified: tests for all the logic, and the app
  still scans and draws (`~/repos` screenshot).
