# App Shell Implementation Plan

**Goal:** `rsdisk [path]` opens a window that scans with live progress, then lets you browse
the result as a sorted list with vim keys, themed from your Zed themes.
**Architecture:** A new `rsdisk` app crate on gpui-pre and gpui-component. Everything that
isn't drawing (settings, theme mapping, list navigation, key sequences) lives in plain
structs with unit tests; gpui views only render them and forward input. The scan runs on a
background thread and the window polls its `Progress`.
**Tech Stack:** gpui-pre `=0.3.9` (imported as `gpui`), gpui-component `0.7.3`, serde_json,
rsdisk-core.
**Spec:** `spec.md` §2.6, §2.9, §2.13 to §2.15, §3.2 (background search), §3.8 (list half),
§3.9, §3.12, §3.13.

## Global Constraints

- Core stays free of gpui (§3.1). Logic that can be tested without a window must be.
- Pin `gpui = { package = "gpui-pre", version = "=0.3.9" }` and `gpui-component = "=0.7.3"`;
  gpui-component pins gpui-pre exactly, so they move together.
- Tim's UI rules: no gradients, no coloured bar on the left edge of a selected row (show
  selection as a filled row), no emoji, no interpuncts as separators.
- Never open a second window while Tim may be typing elsewhere: a new gpui window takes
  keyboard focus and his keystrokes land in it (learned in riff). Check UI by launching
  once and screenshotting with `screencapture -x -l<window id>`; ask before driving keys.
- Riff and Jasmijn are mid-migration to gpui-pre (workmux windows `gpui-pre-migration` and
  `gpui-pre-migration-riff`). Once merged, their AGENTS.md "GPUI traps" notes apply here;
  read riff's before Task 6 (a selection stored as a row index breaks on re-sort; rows in a
  uniform list need `w_full()`).
- Gate before each commit: `cargo test --workspace && cargo clippy --workspace --all-targets
  -- -D warnings && cargo build --release`.

## Plan sequence (this is Plan 3 of 5)

01 core scanner and 02 export and mockup are done. 04 adds the treemap and sunburst into the
right-hand pane this plan leaves as a placeholder. 05 adds marks, Trash, search, rescans.

### Task 1: App crate skeleton

**Files:** create `crates/app/Cargo.toml`, `crates/app/src/main.rs`; modify the workspace
`Cargo.toml` members.
**Interfaces:** binary `rsdisk [path]` (default `$HOME`). Initialises gpui-component and
opens one window titled with the scan root.
**Tests:** none; the gate compiling is the test.
**Steps:** scaffold, gate, launch once, commit.
**Verify:** `cargo run -p rsdisk -- ~/repos` opens a window; screenshot it.

### Task 2: Settings

**Files:** create `crates/app/src/settings.rs`.
**Interfaces:** `Settings { light_theme: Option<String>, dark_theme: Option<String>, visual:
Visual, colour: ColourMode }` with `load(path) -> Settings` and `save(&self, path)`;
`Visual` and `ColourMode` exist now so plan 04 has somewhere to store them. Path is
`~/Library/Application Support/rsdisk/settings.json` (§3.12), created on first save.
**Tests:** round trip; a missing file gives defaults; a corrupt file gives defaults and is
not overwritten until the next explicit save; unknown fields are ignored.
**Steps:** tests first, implementation, gate, commit.

### Task 3: Themes

**Files:** create `crates/app/src/theme.rs`.
**Interfaces:** `Theme` with rsdisk's roles (background, surface, raised, text, dim, faint,
accent, error, selection) plus `kinds: [u32; 8]` indexed by `Kind` (core) in the order of
`Kind::ALL`. `available(dirs) -> Vec<Theme>`, `zed_dirs()`, a built-in light and dark
theme, and `apply(&Theme, cx)` that writes the roles into gpui-component's `ThemeColor`.
**Copy from riff** (`~/repos/private/riff/src/theme.rs`, after its migration lands):
`colour` (hex with alpha blended over the background), `blend`, `zed_dirs`, `available`,
`from_file`, and the shape of its tests. Drop riff's loop/section roles.
**Kind colours** come from the theme's terminal colours: video `terminal.ansi.red`, audio
`terminal.ansi.magenta`, image `terminal.ansi.yellow`, archive `terminal.ansi.bright_yellow`
(falls back to a blend of yellow and red), document `terminal.ansi.blue`, code
`terminal.ansi.green`, app `terminal.ansi.cyan`, other the theme's dim text colour. Missing
keys fall back to the mockup's palette (`mockup/index.html`, `KIND_COLOURS`).
**Appearance:** pick the dark or light theme from settings by the window's appearance and
re-apply when it changes.
**Tests:** role mapping from a sample Zed theme; alpha blending; kind colours read from the
terminal keys; missing keys fall back; nameless themes skipped; every variant in a file
loaded, built-ins first.
**Steps:** tests first, implementation, gate, commit.

### Task 4: Browser state

**Files:** create `crates/app/src/browser.rs`.
**Interfaces:** `Browser` holding the `ScanResult`, the current folder, the selected node
(a `NodeId`, never a row index), and the sort mode. Actions: `down`, `up`, `top`,
`bottom`, `half_page_down(rows)`, `half_page_up(rows)`, `open` (enters the selected folder;
files do nothing), `back` (to the parent, selecting the folder you came from), `jump_to(id)`
(opens its parent and selects it), `cycle_sort` (size, name, file count; selection kept by
id). Accessors for the rows of the current folder and the selected row's index for drawing.
**Tests:** moving clamps at both ends; `open` then `back` restores the selection; `open` on
a file, an unreadable folder or a not-scanned folder does nothing; sorting keeps the same
node selected; half-page moves by half the given row count; an empty folder has no
selection and doesn't panic; `jump_to` a deep node sets folder and selection.
**Steps:** tests first, implementation, gate, commit.

### Task 5: Key sequences

**Files:** create `crates/app/src/keys.rs`.
**Interfaces:** `Keymap::feed(key) -> Option<Action>` that turns keystrokes into the §3.9
actions, holding pending prefixes (`g` waiting for a second `g`). Actions not built yet
(marks, search, trash, rescan, visuals) still parse, so later plans only add handlers.
**Tests:** `gg` gives Top and a lone `g` followed by `j` gives Down; `G`, `ctrl-d`,
`ctrl-u`, `enter`/`l`, `backspace`/`h`, `q`, `?`, `o`, `s`; an unknown key clears a pending
prefix.
**Steps:** tests first, implementation, gate, commit.

### Task 6: Scan screen

**Files:** create `crates/app/src/scanning.rs`; modify `main.rs`.
**Interfaces:** a view that starts `rsdisk_core::scan` on a background thread, redraws a few
times a second from `Progress` (files, bytes, the latest path), and `Esc` cancels (§3.2).
When the scan ends the window switches to the browser view (Task 7).
**Core change:** split `locate_unreadable` so the GUI can probe off the main thread: a
function that takes candidate `(NodeId, PathBuf)` pairs and returns the failures, and one
that applies them to a `ScanResult`. Keep `locate_unreadable` as the composition so the CLI
and its tests don't change; add a test that probe plus apply equals `locate_unreadable`.
The app runs the probe on a background thread after showing the browser and applies the
result when it arrives (§3.2).
**Tests:** the core split as above.
**Verify:** scan `~` from the app: counters move, the browser appears, and some seconds later
the error count settles (screenshot both states).

### Task 7: List view

**Files:** create `crates/app/src/list_view.rs`, `crates/app/src/header.rs`.
**Interfaces:** a virtualized list (gpui-component's `List`/`ListDelegate`, or gpui's
`uniform_list` if the delegate fights the vim keys) over `Browser`'s rows. Each row: name,
size, a thin share-of-parent bar in the kind colour, file count, and a marker for
unreadable, not-scanned and other-volume folders. Selection is a filled row. The header
shows the breadcrumb of the current folder and the totals ("at least" while any error
exists, then the error count with the Full Disk Access hint from §3.13). The right half of
the window is an empty placeholder pane for plan 04.
**Mouse:** click selects, double-click opens, clicking a breadcrumb segment goes there.
**Keys:** routed through `Keymap` into `Browser`; `o` runs `open -R <path>`, `?` shows a
help overlay listing the keys, `q` quits.
**Tests:** none beyond Tasks 4 and 5; this task is drawing and wiring.
**Verify:** browse `~/repos` with only the keyboard: in and out of folders, `gg`/`G`, sort
cycling, help overlay; screenshot. Ask Tim before driving keys if he might be typing.
